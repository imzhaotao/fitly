# 05 · 工程里程碑与质量验收

> 不以压缩工期做功能妥协，按**高水准工程里程碑（M1–M5）**推进：每一步都做到代码整洁、测试充分、3D 体验过关再进下一阶段。

---

## 技术选型与首个可运行版本

先交付手机和电脑都能打开的 Web 应用。首个可演示版本选用一个带用餐区的客厅，让屋主直接打开已布置好的模板、改尺寸、换家具，并在定水电或买家具时看到相应提醒。下表对应[技术架构](03-architecture.md)中的三个工作包。

| 工作包 | 技术 | 负责的事情 |
|---|---|---|
| web | React、TypeScript、Next.js App Router | 模板入口、编辑器、方案对比与分享页面。用 useReducer 管理编辑动作和撤销记录，拖拽结束后保存一次修改。 |
| web 的场景与绘图 | Three.js、React Three Fiber、Drei、浏览器 Canvas 2D | 渲染墙面、家具和尺寸线。家具的长宽高同时驱动模型与测距。Canvas 2D 用于底图校准与描墙。 |
| layout-engine | 纯 TypeScript | 在同一房间内计算家具间距、通行净宽与遮挡。内部统一用毫米，输出测量值、对象 ID 和标注位置。 |
| content | 纯 TypeScript 规则与人工编写的内容 | 点选对象或进入指定阶段时给核对问题；用户补齐尺寸后才执行依赖这些尺寸的判断。 |
| web 的存储与接口 | 本地草稿、Next.js Route Handlers、Drizzle ORM、PostgreSQL | 先支持本机刷新恢复；M4 接入匿名工作区、版本快照、只读短链与投票。 |
| 工程与验收 | pnpm workspace、Vitest、Playwright | 分别验证几何和规则边界、完整操作流程；手机拖拽和视角切换另在真机验收。 |

### 先跑通一间房

| 顺序 | 交付内容 | 验收方式 |
|---|---|---|
| 1. 模板与数据 | 用同一户型制作两套已布置的方案，墙体、门、家具、材质和点位都写入 Plan。打开模板时复制为用户草稿，区分示例点位与屋主已确认的点位。 | 改一套的墙长、桌子尺寸或地板材质，重新打开原模板仍能看到原始设计。 |
| 2. 编辑与试摆 | 从 M2 提前接入一个 3D 场景。先做家具选中、拖动、旋转、换尺寸和切顶视。几何层与画面读取同一份 Plan。 | 在手机上把沙发移近茶几，标注的净距随之变小；撤销后恢复原位置与数值。 |
| 3. 装修避坑 | 将餐桌作为首个访谈案例。水电定位阶段或点选餐桌时，提示用户按桌面用电习惯核对插座位置。已有实测桌高和插座高度时，显示二者的高差。 | 桌面高 750 mm、插座中心高 450 mm 时显示“插座中心低于桌面 30 cm”；缺少实测数据时只显示核对问题。桌下插座本身不计为布局冲突。 |
| 4. 现场试用 | 先让正在装修的屋主打开模板，再按需补自家尺寸，观察是否能独立操作、发现值得核对的细节，并把问题转给家人或师傅。 | 记录哪条提醒促成了量尺寸、改布局或实际询问，以及用户在哪一步退出。用结果决定下一批规则的优先级。 |

这条演示流程建议穿插在 M1、M2 早期完成。餐桌案例属于新增验证样例，暂单列于原有 31 条内容清单之外。完整版本再按下文扩展三空间与规则，M3 接入用户上传的户型图，M4 接入云端分享。上传建图的工作量主要取决于图片质量：先实现“两点定比例、手动描墙、生成可编辑 Plan”，再加入候选墙线识别，两条路径共用同一编辑器。

## M1 · 纯净核心层：`@fitly/layout-engine`、`@fitly/content` 与首批示例户型

**目标**：把核心数学几何、全部 31 条软装避坑规则与首批示例户型做成零依赖、100% 单测覆盖的基石。

- 初始化 `pnpm` monorepo（`layout-engine`、`content`、`web`）
- 实现完整 `Plan` 多房间类型体系（`RoomZone`、`Wall`、`Opening`、绑定墙体的 `Anchor`、支持 L 型的 `FurnitureItem`）
- 实现核心几何原语与 `GeometryQuery`（支持多房间与当前选中对象隔离）：
  - `toPolygons`（含旋转、L 型拆分为双凸多边形、功能朝向边提取）
  - `resolveAnchorPoint`（贴墙点位实时随墙坐标换算）
  - `edgeGap`（返回最短距 + `witness` 最近点）
  - `heightOverlap`（Z 轴高度遮挡判定）
  - `sweptArea`（门扇扫掠区）
  - `pathLength`（厨房三角动线总长）
- 录入 [04-content-seed.md](04-content-seed.md) 全部 **31 条规则（客厅 11 + 厨房 11 + 卧室 9）**，补齐 `ask` 字段并严格自查软装安全红线、L1 核对提问表达与纯 `AND` 触发语义
- **编写 2–3 套典型多空间示例 `plan.json` 及首批可编辑设计模板（例如同一 3.6m 客厅提供“观影优先型”与“亲子活动区型”）**，供 M2 3D 场景直接加载验证
- **验收门**：
  - `layout-engine` 边界用例 Vitest 全绿（贴边、L 型沙发转角空位不误报、共享墙 `side` 门扇扫掠仅命中开门侧、方向净空、高度不遮挡、未校准 `null` 降级）
  - `content` 31 条规则全部通过**保留完整规则的输入边界单测**，重点验收 **“衣柜平开门挡住报警 → 切推拉门后解除 → 未知门型问询”** 与 **“L1 不误报确定结论”**
  - `auditPlan` 静态审计单测全绿：**同一快照下切换选中家具或关闭提示，对比冲突计数差异恒为零**

## M2 · 高质感 3D 引擎与跨端交互系统

**目标**：做出让人眼前一亮的轻量 3D 居家空间，手机端拖拽、桌面端精编都顺手。

- 搭建 Next.js App Router + React Three Fiber 场景：
  - PBR 材质体系（木地板/瓷砖、墙漆、半透门窗玻璃、墙面插座/开关/燃气表立体点位）
  - 柔和环境布光 + `ContactShadows` 接触阴影
  - 多部件参数化家具模型（覆盖客厅/卧室/厨房核心家具与大件家电，支持尺寸规格与配色切换）
- 三视角一键切换：`3D 斜角` / `人眼平视（1650mm）` / `正交顶视`
- **交互细节打磨**：
  - 手机端手势隔离（未选中转视角，选中锁定相机在地面拖移）
  - 智能贴墙吸附、90°/45° 旋转吸附、外置精确微调控件
  - 实时 3D 净空标尺线与避坑脉冲高亮
  - 完整 `undo / redo` 撤销栈
- **避坑交互**：
  - 底部半屏/侧边卡片（同屏最多 1 条 `blocking`、展示实测毫米/厘米数字、一键复制 `ask` 提问清单）
  - 全量列表 + 会话冷却与 24h 关闭记录
- **验收门**：手机（iOS Safari / 安卓微信）与桌面端均能流畅旋转、切换视角、拖拽贴墙并实时触发 3D 高亮避坑。

## M3 · 可编辑设计模板、户型编辑器与底图辅助建图

**目标**：在 M1 首批示例的基础上，补齐同户型多套设计模板、参数化改尺寸与底图辅助描墙校准能力。

- 扩充**可编辑设计模板库**：覆盖两居/三居、竖厅/横厅，同户型提供不同功能取舍的完整布局供用户直接开改
- **参数化房间编辑**：点击墙体/房间修改开间、进深、门窗位置与基于墙体朝向（`side`）的开门方向，贴墙 `Anchor` 自动跟随墙体移动，3D 实时联动更新
- **2D 户型图底图辅助建图**：
  - 上传平面户型图片作为半透明底图
  - 浏览器端 Canvas 灰度二值化 + 直线段候选提取 + 两点比例尺校准（标定一段已知墙长）
  - 交互式绘制墙体、自动角点吸附、放置门窗与贴墙点位（含离地高度）
- **验收门**：未校准状态严格降级返回 `null` 不误报；校准后生成的 `Plan` 与内置模板一样能完整跑通 3D 渲染与避坑检测。

## M4 · 云端持久化、多版对比、短链分享与家人投票

**目标**：打通“保存快照 → 任意两版对比 → 发给家人投票定案”的全栈闭环。

- Drizzle ORM + 数据库 Schema 与迁移（`plans`、`snapshots`、`shares`、`votes`、`events`）
- 匿名工作区免登录持久化 + 自动快照列表 + 手动命名版本
- **任意两版对比视图**：支持同场景 3D 幽灵轮廓叠加与分屏对比，直接给出尺寸与避坑数量差异报告
- **SSR 短链分享页 `/s/[code]`**：
  - 服务端渲染清晰标题与预览摘要（适配微信分享卡片）
  - 家人免登录 3D 只读查看 + 点击投票选版 + 留一句话批注
- 接入服务端核心漏斗埋点（`plan_entered`、`item_moved`、`view_switched`、`pitfall_acted`、`snapshot_compared`、`plan_shared`、`share_opened`、`vote_submitted`）
- **验收门**：Playwright 端到端测试覆盖“选/建户型 → 拖家具触发避坑 → 修正消除问题 → 保存两版对比 → 分享短链 → 家人投票”主链路全绿。

## M5 · 真实用户测试、内容复核与上线

- 找 5–10 位真实装修中屋主在手机微信/桌面端走完全流程，记录卡点并优化体验
- 请经验丰富的独立监理/施工队长复核 31 条内容（重点确认 `blocking` 归类与提问清单实用性），逐步标为 `verified: true`
- 部署生产环境，发布小红书首批真实 3D 试装对比案例，观察以下核心信号：

| 信号 | 核心事件 | 判断标准 |
|---|---|---|
| 建得出、摆得动 | `plan_entered` / `item_moved` | 用户能顺利进入并多次拖动、切换视角 |
| 避坑真有用 | `pitfall_acted` | 触发提醒后主动换尺寸、挪位置或复制 `ask` |
| 对比与协同有效 | `snapshot_compared` / `plan_shared` / `vote_submitted` | 主动做方案对比，并把短链发给家人产生真实打开与投票 |
