# 05 · 两周排期与验证

> 两周的目标不是"做完产品"，是**拿到一个能发出去、能被 10 个人试、能读出结论的东西**。

---

## D0：开工前必须搞定的三件事（不加进两周里）

| # | 事项 | 没有它的后果 |
|---|---|---|
| 1 | **定一个小区的纸质/电子户型图**，确认可授权使用 | 第一天就卡住，所有几何代码没数据可测 |
| 2 | **找到一位施工队长/监理**，约好 1–2 小时审内容 | 30 条内容上线了但没人敢信 |
| 3 | **买域名 + 启动备案**（个人主体要提前问要求） | 最后一天发现国内打开不了 |

这三件都不难，但都要等。**Day 1 之前办，别边写代码边等。**

## 第 1 周：把"能算准"做出来

### Day 1–2 · 几何内核

- 建 pnpm workspace，三个包空壳
- 写 `toPolygon` / `edgeGap` / `sweptArea` / `intersects` 四个原语
- **先写测试再写实现**：贴边、旋转 45°、门扇刚好擦过、两条墙夹角
- 产出：`@fitly/layout-engine` 单测全绿

> 这一层如果手感不对（间距算错 5cm），后面所有东西都白做。**宁可多花一天。**

### Day 3 · 户型数据结构 + 第一套户型

- `Plan` 类型定稿，写一个手工建模的 `plan.json`（客厅 + 墙体 + 门窗 + 插座点位）
- 写 `query.ts`，把 4 个原语拼成 `GeometryQuery`
- 产出：能在命令行读一个 JSON，打出一段"沙发到插座 = 120mm"

### Day 4–5 · 渲染与拖拽

- Vite + React 起 `@fitly/web`
- SVG 渲染墙体、门窗、锚点、家具
- 指针拖拽 + 旋转 + 缩放视图
- **undo/redo 栈**（Day 5 必做，不是"以后再说"）
- 产出：能在手机浏览器里拖一个沙发

### Day 6–7 · 尺寸显示

- 物件之间实时显示净空数字
- 选中态、吸附、越界提示
- 移动端视口适配（手机竖屏优先，不是把桌面版缩小）
- 产出：拖动时能看到"还剩 320mm"

**第 1 周结束的验收**：手机打开链接，选户型，拖沙发，看到真实间距，能撤销。**其他什么都没有。**

## 验证指标

| 指标 | 事件 | 看什么 | 危险信号 |
|---|---|---|---|
| 进得来 | `plan_open` → `plan_entered` | 多少人真的进到试摆 | 打开就走 → 落地页没讲清 |
| 摆得动 | `item_moved` / session | 一次会话挪几次 | 只挪 1–2 次 → 手感差或不懂怎么用 |
| 看得懂 | `pitfall_expanded` / `pitfall_shown` | 展开率 | 展开率极低 → 标题没说服力，或提示是噪音 |
| 改得对 | `pitfall_acted` | 提示后有没有改方案 | 看到 100 次 0 次行动 → 内容无效 |
| 愿意存 | `plan_saved` | 保存率 | 没人存 → 方案不值得留下来 |
| 愿意发 | `plan_shared` / `share_opened` | 分享率 + 打开率 | 发了没人点 → 家人根本不关心（这比技术问题严重） |

**最重要的两个数**：`pitfall_acted`（内容有没有用）和 `plan_shared`（这件事是不是本来就该发生）。

## 决策门

两周后按这三档走，别含糊：

| 结果 | 判断 | 下一步 |
|---|---|---|
| 有人试完改了方案、还发给了家人 | ✅ 成立 | 加第二个小区、第二个空间（厨房）；开始做小程序承接分享 |
| 有人愿意试，但没人发 | ⚠️ 半成立 | 产品对，但"发给家人"这个假设错了 → 改分享形态，别加功能 |
| 没人愿意试第二次 | ❌ 不成立 | **别做小程序，别加功能。** 回去改核心动作，或换问题 |

### 什么时候该上小程序

只需要一条：**大量用户卡在"发给家人"，而且埋点显示链接发出去后打开率很低。**

这时候小程序的价值是「微信卡片 + 最近使用」，不是"更快的加载速度"。

**反过来，如果试了两个月没人分享，那就永远不该做小程序。**

## 如果两周做不完

按这个顺序砍，从下往上：

1. 埋点（先用最简单的计数，甚至人工问）
2. A/B 两版（先只支持存一版）
3. 除客厅外的任何东西
4. 30 条内容 → 12 条（客厅那 12 条先上）
5. 分享链接 → 先让用户截图

**唯一不能砍的是：拖拽 + 真实间距 + 至少 5 条能触发的坑。** 这是产品的最小骨架。

## 一个更省的路，值得先想

如果你认识某个小区的业主群、物业，或者有装修公司的关系：

**前 10 个用户可以用微信接单，手动帮他们出一版方案。** 一次 30 分钟，你能直接听到他们真正纠结什么尺寸问题。

这比任何埋点都准，而且不用等两周。**能先跑人，就别先跑代码。**
