# 00 · 项目上下文

> 这份文档写给两类读者：**未来的自己**，和**接手代码的人 / AI 助手**。
> 如果只读一份文档，读这份；它解释"为什么是这个样子"。

---

## 1. 这个项目从哪来

起点是一个个人想法：做一个叫**「装修匠」**的装修 App。

最初的设计是**平台模式**——让装修师傅入驻，用户在平台上找师傅、比价、下单。这个方向被自己否掉了，原因有三个：

1. **师傅不缺活。** 好师傅手上排期都排到几个月后，没有动机入驻一个新平台。
2. **管不住。** 参考啄木鸟这类平台，师傅进来后坑蒙拐骗、报价不透明的问题极难治理。
3. **水太深。** 装修涉及水电、防水、燃气、承重，一次出事的成本远高于平台能收的佣金。

于是转向了**工具模式**：让用户上传/选中自己的户型，在手机里试摆家具、换材质，把"装完才发现不对"提前到"下单之前"。

## 2. 关键演变：两次认知修正

### 修正一：从"生成好看的效果图"到"能改、能比、能量"

第一版的想法是"上传平面图 → 生成 3D 效果图"。这个想法的问题是：**效果图只能给灵感，不能帮做决定**。

用户真正的困惑是"2.8 米的沙发进不进得去"，不是"我家 3D 长什么样"。所以产品重心从**渲染**转到**尺寸和间距**：能随时改、能存两个版本比较、能看到过道还剩多少。

### 修正二：从"做一堆功能"到"只做一个动作"

中途考虑过加社区、广场、探索、家具广告入驻、装修知识库、师傅对接。这些后来全部推迟。

原因是：核心动作只有一个 —— **用户愿不愿意用自家户型试摆，并把结果发给家人一起选。** 这个动作没被验证之前，加任何功能都是在给一个还没被需要的东西做装修。

## 3. 已经定下来的决策（ADR 简表）

| 编号 | 决策 | 状态 | 理由 |
|---|---|---|---|
| D1 | 放弃师傅入驻 / 平台模式 | ✅ 采纳 | 供给侧没动机，履约风险不可控 |
| D2 | 从"生成效果图"转向"可试摆、可比较" | ✅ 采纳 | 效果图给灵感，间距才帮做决定 |
| D3 | 先做 Web（手机优先 H5） | ✅ 采纳 | 当前最大未知数是交互手感，需要一天改五遍的载体 |
| D4 | 第一版不做 3D，只做 2D 俯视 + 尺寸 | ✅ 采纳 | 决策靠间距不靠渲染；砍掉约 60% 工作量 |
| D5 | 户型来源：**小区户型库优先**，上传户型图兜底 | ✅ 采纳 | 普通用户不知道自己户型图长啥样；同时解决精度来源问题 |
| D6 | 避坑内容做成**触发器**，不是知识库 | ✅ 采纳 | 与几何数据联动，是唯一别人抄不走的部分 |
| D7 | 英文名 / 仓库名 **Fitly** | ✅ 采纳 | npm 未被占用，短，可作 scope（`@fitly/*`） |
| D8 | 不做全国户型库 | ✅ 采纳 | 成本黑洞，无法支撑单人开发 |
| D9 | 社区 / 广场 / 评论 / 家具商城 | ⏸ 推迟 | 等单点动作验证后再说 |
| D10 | 小程序 | ⏸ 推迟 | 见 05 的切换条件 |

### 被明确否决的方案

| 方案 | 否决原因 |
|---|---|
| 师傅入驻平台 | 供给侧没有动机，履约风险高 |
| 全屋 3D 实时渲染 | 单人两周做不完，且不是决策必需 |
| 小程序先行 | 每次改动要提审 1–3 天，拖死交互试验 |
| 独立 App | 低频工具，获客成本压死项目 |
| 全国户型库 | 需要持续投入，抢不过酷家乐 |
| 装修知识百科 | 用户在用工具时不会读百科，必须挂在决策点上 |
| 家居电商 | 先测"用户会不会点商品"，不先建商城 |

## 4. 现实的约束条件（写代码前必须承认的）

- **单人开发**，可投入时间以"两周内做出可上线的东西"为上限。
- **主打中国市场**，用户在微信里分享、在小红书里找灵感。
- 技术栈偏 **TypeScript / React**，这是唯一能保证两周交付的选择。
- **没有现成的户型数据**，第一批靠人工建模，必须能拿到授权图纸。
- **没有内容团队**，前 30 条避坑内容需要自己写 + 找懂行的人核一遍。

## 5. 词汇表

| 词 | 含义 |
|---|---|
| **户型** | 一套房子的平面结构：墙、门窗、房间边界。Fitly 里等价于 `Plan` |
| **试摆** | 把家具拖进户型并改变位置/尺寸，实时看间距 |
| **间距 / 净空** | 两个物体之间可通行的距离，如"沙发到茶几""床到衣柜" |
| **校准** | 给图纸标定真实尺寸（标一段已知长度的墙） |
| **触发器** | 决定某条避坑提示"什么时候出现"的条件 |
| **坑** | 一条装修中容易踩错、且后果不可逆或昂贵的具体问题 |
| **A/B 版** | 同一户型的两个方案快照，用来对比 |
| **blocking / costly / annoying** | 坑的严重度分级，决定提示强度 |

## 6. 还没想清楚的问题（Open Questions）

> 这些不阻塞第一版，但要在两周内找到答案。

1. **第一批做哪个城市、哪个小区？** 图纸授权从哪来？
2. **尺寸校准的真实失败率有多高？** 用户标完之后，误差是 5cm 还是 30cm？
3. **"发给家人"要不要支持批注？** 家人看完点个"我选 A" 还是只能回微信说？
4. **内容由谁核？** 找一个真实施工队长做审校，成本多少？
5. **中文名保留「装修匠」还是换？** 英文 Fitly 已定，中文名是否要跟着改（避免"匠"暗示找师傅）？
6. **小红书怎么导流？** 站内不能放外链，是走"私信发链接"还是"评论区引导"？
